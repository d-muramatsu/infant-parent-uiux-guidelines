# 赤ちゃんと保護者のための UI/UX ガイドライン

乳児を画面に長く留めるのではなく、**保護者の負担を減らし、親子のやり取りと画面外の生活を支える**ための日本語実践ガイド。

確認日：2026-11-14 ／ 初版 0.1

> 独立した設計提案です。医療・発達評価・法律上の助言、認証規格ではありません。AAP、ETSI、UNICEF等の公式ガイドラインの翻訳版でも、各団体が承認した文書でもありません。公開情報を読み、出典の内容と本プロジェクトの設計判断を区別しています。

## 使い方

1. 下記で対象と利用目的を決める。
2. 必須項目を設計に組み込む。
3. [レビューと試用テンプレート](REVIEW.md)で、未確認も含めて記録する。
4. [出典と適用限界](SOURCES.md)を参照し、製品固有の判断を残す。

「必須」「推奨」は**このプロジェクトのレビュー基準**であり、法的義務や引用元の規定と同義ではありません。

## 1. 対象を分ける

本書では乳児を原則0〜11か月とし、12〜35か月の幼児は隣接対象として区別する。月齢は設計上の分類であり、できることの保証ではない。早産・障害・発達差・感覚特性・家庭の言語を想定する。

| 利用形態 | 主な利用者 | 設計の入口 |
|---|---|---|
| 育児記録・予定・情報検索 | 保護者 | 片手、寝不足、中断、複数養育者、誤入力の回復 |
| 親子で見る・触るコンテンツ | 保護者と子 | 保護者が開始・停止し、子の反応を見ながら使う |
| 家族とのビデオ通話 | 大人が媒介する親子 | 相手・映像・音声の管理、相互の応答 |
| 子どもの単独・長時間利用 | 乳児には採用しない | 見守りや対面交流の代替にしない |

**根拠の要約**：AAPは乳児の画面利用を抑え、共に見て、遊びなどを置き換えないよう勧める。ZERO TO THREEも現実の遊びと会話を重視する。[A][Z]

画面を使っただけで発達が改善すると宣伝しない。タップ、凝視、滞在時間を「学習」「理解」「幸せ」の証拠にしない。

## 2. 最初に決めること【必須】

- その目的は、紙・おもちゃ・保護者の声だけでも達成できるか。
- 子どもに画面を見せる必要があるか。保護者だけに説明し、画面外で遊べないか。
- 成功指標は何か。連続視聴時間や再訪率ではなく、用事の完了、誤操作の減少、終えやすさを優先する。
- 対象月齢、想定端末、保護者の関与、使わない場面を短く表示する。
- 「1時間釘付け」「泣き止み保証」「知能が伸びる」など未検証の効果を約束しない。

## 3. 親子コンテンツの基本【必須】

### 3.1 子どもの注意を奪い続けない

- 自動再生、無限スクロール、連続ログイン報酬、失うと損をする仕組みを設けない。
- 同じ操作には予測しやすい反応を返す。ランダムな高額報酬風演出や、連打を要求する仕組みを避ける。
- 休止と終了を常に使えるようにする。終了時にキャラクターを泣かせたり、保護者を責めたりしない。
- 自然な区切りを置く。特定の分数を「安全な時間」と称しない。例えば3分タイマーは製品上の区切りであり医学的基準ではない。
- 眠そう、不快そう、顔をそむける等の反応があれば、タイマーを待たず保護者が終えられる。

### 3.2 人とのやり取りを中心にする

- 「一緒に『ばあ』と言ってみよう」など、保護者への短いきっかけを添える。
- 会話や実物の遊びに移る余白を置く。何もしない時間に音や動きで呼び戻さない。
- 読字、指示の理解、正確な指先操作を子に要求しない。
- 子の操作がなくても失敗表示や減点をしない。
- 画面の存在を隠して人間のように振る舞うAIや、親代わりの愛着対象としての訴求を避ける。

## 4. 視覚・音・入力の設計

以下は主に本書の設計提案。特定月齢への効果を実証した仕様ではない。

### 視覚【必須】

- 画面の主役を絞り、操作対象と装飾を区別する。
- 急な全画面切替、点滅、強いズーム、驚かせる演出を使わない。
- 動きを減らす設定を尊重し、動きなしでも目的を達成できる代替を用意する。
- 写真・絵・色だけに依存せず、保護者が読める名前・説明を持たせる。
- 「赤ちゃんは必ず原色が好き」などの固定観念で刺激を増やさない。

### 音【必須】

- 初期状態で無音とし、保護者が明示的に有効化する。音なしでも使える。
- 音の重なりや連打による増幅を防ぎ、停止時と画面を離れた時に止める。
- 音量変更とミュートを分かりやすくする。
- Webの音量値だけから実際の音圧や聴覚上の安全を保証しない。端末・距離によって変わる。
- ヘッドホンを乳児の標準利用として案内しない。

### 入力【必須／推奨】

- 大きく離れたタップ対象を使う。端やブラウザーのジェスチャー領域に重要操作を置かない。
- スワイプやドラッグだけでしか進めない作りを避ける。連打・複数指・押したままでも破綻しない。
- 子ども用領域から購入・外部サイト・送信・データ削除へ直接進めない。
- 保護者用操作は明確に分ける。ただし複雑な謎解きを「保護者認証」と称しない。
- 誤タップ防止の工夫は認証・認可の代替ではない。機微な操作には適切な確認と権限管理が必要。

## 5. 保護者の UI【必須】

- 最初の画面で「何ができるか」「音が出るか」「どう終えるか」を伝える。
- 抱っこしながらの片手操作、中断、明るい屋外・暗い室内、低速回線を想定する。
- 保存済み／未保存／送信中／失敗を区別する。「完了」は保存を確認した後だけ表示する。
- 戻る・再読込・アプリ切替で、記録の消失や二重登録を起こさない。
- 入力のやり直しを容易にする。日付・単位・対象の子の取り違えを防ぐ。
- 通知は必要なものを選べるようにし、深夜や催促の多さを既定にしない。
- 「毎日できていません」「ほかの赤ちゃんはできています」など、罪悪感や比較を利用しない。
- 家族構成を「父・母」だけに固定しない。養育者の役割、言語、支援機器を考慮する。
- 医療相談が必要な内容と一般的な育児情報を区別し、症状から自動で診断しない。

## 6. アクセシビリティ【必須】

WCAG 2.2 AAをWebの基礎目標とする。ただしチェック項目の一部だけを満たして「WCAG準拠」と宣伝しない。[W]

- キーボードだけで保護者の主要操作を完了でき、フォーカス位置を確認できる。
- ボタンは意味のある名前を持ち、スクリーンリーダーで状態も分かる。
- 通常文字のコントラストは原則4.5:1、大きな文字は3:1。色だけで状態を伝えない。
- 文字拡大や狭い画面で操作が欠けない。縦横どちらかに不必要に固定しない。
- 動画に字幕等の適切な代替を用意する。親向けの音声指示を文字でも示す。
- 停止ボタンや設定をスクリーンリーダーから隠さない。
- WCAG 2.2の2.5.8（AA）は24×24 CSS pxを基準に例外を含む。2.5.5（AAA）の44×44 CSS pxとは区別する。
- 本書では主要ボタンを原則44×44 CSS px以上とする設計目標を推奨し、実機で間隔も確認する。乳児に適したサイズと保証するものではない。

## 7. 安全・プライバシー【必須】

以下はデータを必要最小限にする本書の製品方針。国・地域ごとの法令適合は別途確認する。

- 遊びに不要ならアカウント、氏名、顔写真、生年月日、位置情報を要求しない。
- 月齢が必要なら、正確な誕生日の収集以外の方法を検討する。
- カメラ・マイクは既定で使わない。必要な場面で目的を説明し、拒否しても使える代替を示す。
- 子どもの画像・声・記録を広告、顔識別、推測プロファイル、AI学習に流用しない。
- 家族共有は既定で非公開。招待先、対象データ、権限を確認でき、取り消せるようにする。
- localStorageは端末内であっても秘密の金庫ではない。機微な記録や認証情報を安易に入れない。共有端末、XSS、削除方法を検討する。
- 保存する場合は目的・保存先・保持期間・削除方法を説明する。保存しない設計も選択肢にする。
- 子ども向け画面に広告・課金誘導・第三者トラッキングを置かない。
- ブラウザー画面はチャイルドロックでも見守り装置でもない。OS操作や端末落下を防げると表示しない。
- 端末・充電ケーブルの置き方を含め、大人が見守る利用を案内する。乳児に端末を預けて離れることを勧めない。

## 9. リリース前の確認

「子どもが長く見た」ではなく、以下を確認する。

- 保護者が迷わず停止・消音できたか。
- 操作を中断して戻った時に予期しない音・課金・送信が起きないか。
- 記録を間違えても回復できるか。
- 子の反応に合わせてすぐ終えられるか。
- アクセシビリティ、権限拒否、通信失敗、低性能端末で主要機能が使えるか。
- 未検証の年齢・端末・環境を明記したか。

子どもとの試用では保護者の同意を得て、嫌がる反応を尊重する。録画しなくても評価できる方法を優先し、長時間使わせる実験をしない。専門家レビューや小規模試用だけで全乳児への安全性・教育効果を保証しない。
